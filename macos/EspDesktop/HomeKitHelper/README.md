# EspDesktop Home prototype

Apple Home cards let you tap a paired EspDesktop display to run a scene or
control an accessory through your Mac. The prototype supports scenes you created
in Apple Home, open and close for compatible blinds, and on and off for
compatible lights, switches, outlets and fans.

## Add an Apple Home card

Use the experimental EspDesktop Mac build, its signed **EspDesktop Home**
helper and a display paired over Wi-Fi with firmware that supports the version 2
layout API. Check that your home appears in Apple Home on the Mac.

1. In EspDesktop on the Mac, open **Settings → Displays** and click **Device**
   next to your display. Select an empty tile and choose **Apple Home**.
2. EspDesktop connects automatically. Allow HomeKit access when macOS asks.
   If only one home is set up, EspDesktop selects it automatically. If a home
   picker appears, choose your home and click **Continue**. EspDesktop remembers
   the choice and reconnects in the background the next time it starts.
3. Pick a control. The Mac editor lists every supported
   control in the connected home. The display's browser editor shows only the
   controls already saved for that display.
4. Enter the label you want on the touchscreen in **Display Label**, then
   click **Save**. The editor shows the icon the card will use. You can keep it,
   apply the suggested icon, or choose another under **Card Settings → Icon**.
5. With your Mac awake and unlocked, tap the card and check that the accessory
   responds. The helper may briefly come forward if HomeKit requires foreground
   access, then return focus to the previous Mac app.

If the list is empty or access was denied, check **System Settings → Privacy &
Security → HomeKit** for **EspDesktop Home**, then make sure the selected home
has a compatible accessory or a scene you created.

## Apple Home card icons

For new cards, the editor picks an EspDesktop icon from the display label you
type. For example, **Open blind** uses an up arrow, **Close blind** a down
arrow, and **Office fan** a fan. Labels without a match use the house icon.
Existing cards keep their saved icon when you edit the label.

The Mac also shows a suggestion based on the Apple Home control if it differs
from the current icon. **Use suggested** applies it explicitly. HomeKit exposes
the accessory service type and scene actions. Its public API has no field for
the icon chosen in Apple Home. [Accessory service types](https://developer.apple.com/documentation/homekit/accessory-service-types) · [Scene API](https://developer.apple.com/documentation/homekit/hmactionset)

The Mac uses HomeKit data to make the suggestion locally. The display
stores the EspDesktop icon with your label and an action
reference generated by EspDesktop. Home names, scene names, HomeKit identifiers
and accessory data stay on the Mac. Review the terms before adding any automatic
transfer of HomeKit-derived information. [Apple Developer Program License Agreement, §3.3.3(I)](https://developer.apple.com/support/terms/apple-developer-program-license-agreement/)

## Build the test apps

The companion build requires `ESPDESKTOP_EXPERIMENTAL_APPLE_HOME=1` and the
repository's Node dependencies to bundle the Device Settings editor. The helper builds
separately from `EspDesktopHome.xcodeproj`. Open the project in Xcode, select the
**Mac Catalyst** destination and use an Apple Development identity and HomeKit
provisioning profile from the same team as the signed companion. Include the test
Mac in that profile. If Xcode reports that the new app ID is missing the HomeKit
entitlement, build once for the generic iOS destination with automatic signing,
then rebuild for Mac Catalyst. Install the signed Mac helper in `~/Applications`
and open it once so macOS can find it. The companion checks the helper's signing
identity before launching it. Release updates are disabled in the experimental
companion build so it can stay on the feature branch during testing.

Confirm a supported HomeKit entitlement path before distributing this feature
in a public release.
